# Plan 3：并行——独立分析后统一汇总

## 模式定义

并行模式把彼此独立的子任务同时启动，等待所有结果后再合并：

```text
             -> 市场分析  --\
用户任务 ->                  -> 汇总结论
             -> 监管分析  --/
```

它适用于同一材料的多角度分析、多个数据源同时查询或互不依赖的子任务。并行的价值是降低总延迟和增加视角；若两个任务存在先后依赖，并行会得到缺少上下文的错误结果。

## 关键概念：Fan-out 与 Fan-in

`Fan-out` 是把输入分发给多个分支，`Fan-in` 是等待并合并输出。只有分发而没有汇总，调用方会得到一堆零散答案；只有汇总而没有并行，则只是普通提示链。

并行任务的总耗时通常接近最慢分支，而不是所有分支耗时之和。因此需要为每个分支设置超时或允许部分结果，否则一个卡住的分支会拖住最终输出。

## Eino ADK 映射

测试用 `adk.NewParallelAgent` 启动两个子 Agent，再由 `parallelMergeAgent` 收集分支事件并生成汇总结论。`blockingAgent`
使用统一的 release 信号：只有两个分支都报告已启动后，测试才允许它们结束，从而真正验证并发启动，而不是只根据很不稳定的耗时猜测。

Eino v0.9.19 同样对 `ParallelAgent` 的生产多 Agent 使用给出提示，建议多数复杂场景考虑 `ChatModelAgent + AgentTool` 或
DeepAgent。本例重点是理解并行拓扑和事件汇聚。

## 生产边界

- 并行只用于互不依赖的工作。
- 汇总结果不要依赖分支完成顺序，因为并发顺序不稳定。
- 明确“部分失败是否仍返回”，并在结果中标记缺失分支。
- 限制最大并发数，避免同时调用太多模型或外部 API。
- 所有分支从同一个总 `context` 派生，便于统一取消。
