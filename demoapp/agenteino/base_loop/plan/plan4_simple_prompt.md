# Plan 4：编写简单 Prompt

## 本节只解决什么

写一个没有变量、没有模板引擎的简单 Prompt：稳定规则放在 system 消息，具体任务放在 user 消息。

## 理论基础

Prompt 是给模型的输入规范，不是魔法咒语。初学时最可靠的结构是：

1. 在 system 中声明角色、目标、输出语言和硬约束。
2. 在 user 中放本次的真实问题和必要数据。
3. 要求一个可检查的输出，例如“一句话、中文、不编造未提供的数据”。

把稳定规则和可变问题混成一段大字符串，短期能跑，但后续添加历史、模板、工具时很难维护。Eino 的消息模型天然支持这种分离。Plan 4 的代码故意不格式化变量，只验证两条静态消息的结构；下一节才引入模板。

好的入门 Prompt 要具体但不过度复杂。比如“你是 Go 助教；用不超过三句话解释概念；不知道时说不知道”比“你是世界上最聪明的专家”更可测试。它仍不能保证模型永远服从，因此关键业务规则不能只依靠 Prompt。

## 动手步骤

```bash
go test ./testfiles -run TestPlan4StaticPrompt -v
```

阅读测试中 system 与 user 的内容。把输出限制从“一句话”改成“三个要点”，然后在真实模型测试中观察输出变化（可复用 Plan 2 的客户端）。

## 本节验收

能把“长期规则”和“本轮问题”分别写进 system 与 user。下一节学习把问题中的变化部分安全地填入模板。
