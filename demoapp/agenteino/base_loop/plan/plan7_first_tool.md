# Plan 7：编写第一个本地工具

## 本节只解决什么

把一个普通 Go 函数包装为 Eino `Tool`，让它能接收 JSON 参数、执行确定性逻辑并返回文本结果。示例使用加法，避免网络和外部状态干扰。

## 理论基础

模型只能生成文本或工具调用意图，不能直接安全地执行你的 Go 代码。Tool 是两者之间明确的边界：它向模型声明名称、描述和参数 schema；框架收到模型的调用请求后，再把 JSON 参数解析为 Go 结构体并执行受控函数。

`utils.InferTool` 很适合入门。你提供输入结构体、工具名、用途说明和 Go 函数，Eino 从结构体推导参数 schema。工具名应稳定、简短；描述要说明**何时使用**和参数含义。模型依赖这些元数据来决定是否调用工具，因此“把所有业务说明都塞进函数实现”对模型没有帮助。

工具不是无害的函数调用。真实工具可能扣款、写数据库或访问用户数据，需要权限、输入校验、超时、审计和幂等性。先从纯函数加法开始，是为了把 Agent 编排与副作用风险分开学习。
