# 前端 TODO · DB 开发规范检查 Web

## 目标与原则

在 `p_frontend` 实现免登录、桌面优先的单页 Web 应用。用户不需要账号即可通过粘贴数据库 URL 或逐项填写连接信息来提交检查、观察进度、查看分级报告和下载 SQL 建议。

- 首期不提供账户、权限、历史跨设备同步；`localStorage` 只保存不含凭据的最近任务摘要和筛选条件，`sessionStorage` 只保存当前会话所需的短期任务访问令牌。
- 连接密码仅存在于提交表单和请求过程中；不得写入 `localStorage`、`sessionStorage`、URL、前端日志或错误提示。
- 页面文案使用“紧急 / 一般 / 建议”三级等级，不直接展示后端枚举值。
- 以可访问性为基线：键盘可操作、表单有标签、状态使用文字而非只依赖颜色、窄屏可阅读。

## 技术栈与前端架构

以快速完成连接、进度和报告闭环为目标，首期采用单体 SPA，不使用 SSR、微前端或复杂的全局状态方案。

| 领域 | 选型 | 使用原则 |
| --- | --- | --- |
| 应用框架 | Vue 3 + Composition API + TypeScript | 页面、组件和 API 数据均使用类型定义，优先采用组合式函数复用轮询、筛选等逻辑 |
| 构建工具 | Vite | 保持默认开发/构建流程，按环境变量配置 API 基地址 |
| UI 组件 | Element Plus | 直接使用 Form、Table、Drawer、Progress、Steps、Tag、Dialog、Pagination、Message 等组件，避免重复造基础控件 |
| 路由 | Vue Router | 维护新建检查、任务进度、报告、报告预览和任务记录等页面路由 |
| 客户端状态 | Pinia | 仅保存 UI 状态、最近任务 ID、筛选条件和任务进度缓存；严禁保存 URL、密码或完整连接串 |
| 请求层 | Axios | 统一配置 API 基地址、超时、错误映射和脱敏日志；服务端数据以接口返回为准，不复制为复杂全局状态 |
| 图表 | 首期不引入 | 三级统计优先使用 Element Plus 的统计卡与进度条；P1 确有复杂图表需求时再按需引入 ECharts |

### 目录约定

```text
src/
├── api/            # tasks、reports 等 Axios 请求封装
├── components/     # 可复用业务组件：ConnectionForm、WorkerProgress、FindingDrawer
├── composables/    # useTaskPolling、useReportFilters、useConnectionForm
├── layouts/        # AppLayout
├── router/         # Vue Router 路由和导航守卫
├── stores/         # Pinia：任务缓存、最近任务、页面筛选状态（无凭据）
├── types/          # 与后端契约对应的 Task、WorkerProgress、Finding、Report 类型
├── utils/          # 脱敏、时间格式化、下载与错误映射
├── views/          # 页面：Home、TaskProgress、Report、ReportPreview、History
├── App.vue
└── main.ts
```

数据流保持单向且简单：`View → composable / api → Go API`；接口结果写入当前页面状态，需要跨页面保留的少量非敏感 UI 数据才进入 Pinia。`useTaskPolling` 负责轮询启动、退避、停止与页面卸载清理，不能在多个组件中重复创建定时器。

## 页面与导航

| 页面 | 路由建议 | 用途 |
| --- | --- | --- |
| 新建检查 | `/` | 填写连接信息、选择检查范围和规则，提交任务 |
| 检查进度 | `/tasks/:taskId` | 展示采集/分析进度、阶段日志和可恢复错误 |
| 体检报告 | `/reports/:taskId` | 展示等级统计、问题列表、筛选、详情与 SQL 建议 |
| 报告预览 | `/reports/:taskId/preview` | 在线预览完整的 Markdown/HTML 报告，并可下载同一报告快照 |
| 任务记录 | `/history` | 展示本浏览器最近任务，密码永不保存 |

## 前端原型设计

### 1. 新建检查页

```text
┌───────────────────────────────────────────────────────────────────┐
│ DB Inspector                                      最近任务  帮助     │
├───────────────────────────────────────────────────────────────────┤
│ 数据库体检                                                             │
│ 使用只读账号连接数据库。不会读取业务数据，也不会直接执行修改。              │
│                                                                       │
│ 连接方式  [数据库 URL] [逐项填写]                                     │
│                                                                       │
│ 数据库 URL [ mysql://readonly:password@127.0.0.1:3306/app_db ]       │
│ 格式示例：mysql://用户名:密码@主机:端口/数据库                         │
│                                                                       │
│ 切换至“逐项填写”后：                                                    │
│ 数据库类型 [ MySQL v ]       主机 [ 127.0.0.1              ]          │
│ 端口       [ 3306     ]      数据库 [ app_db                 ]         │
│ 用户名     [ readonly ]      密码   [ •••••••••••••••••••• ]          │
│                                                                       │
│ 检查范围  (•) 全部表   ( ) 指定表 [ 输入表名，逗号分隔             ]      │
│ 规则集    [ 内置基础规则 v ]   [ ] 隐藏报告中的对象名称                 │
│                                                                       │
│ 说明：密码仅用于本次检查，任务结束后立即清除。                             │
│                                            [开始检查]                 │
└───────────────────────────────────────────────────────────────────┘
```

连接方式以标签页或单选项互斥切换：URL 模式仅显示**普通文本**的数据库 URL 输入框，逐项模式仅显示主机、端口、数据库、用户名和密码。切换时清空另一种方式中包含凭据的内容，避免重复提交或浏览器残留。校验策略：URL 模式校验协议、主机、端口和数据库名；逐项模式校验必填项和端口格式；提交按钮在请求中禁用；连接失败时在表单顶部显示可操作的错误信息，不回显密码或完整连接串。

### 2. 检查进度页

```text
┌───────────────────────────────────────────────────────────────────┐
│ ← 返回首页   检查 #20260902-001                  进行中  62%          │
├───────────────────────────────────────────────────────────────────┤
│ [采集 Schema] ━━━━━━━━━━━ [规则分析] ━━━━━━━━··· [生成报告] ···      │
│                                                                       │
│ 已处理 31 / 50 张表       预计剩余：约 1 分钟    [暂停] [取消检查]      │
│                                                                       │
│ Worker 进度                                                          │
│  ✓ Schema 采集         50 / 50   已完成                              │
│  · 命名规范检查         31 / 50   正在检查 orders                    │
│  · 索引与性能检查       31 / 50   正在检查 orders                    │
│  · 类型与约束检查       28 / 50   正在检查 order_items               │
│  ○ DML 建议生成         --        等待中                              │
│                                                                       │
│ 提示：关闭页面后可在“最近任务”继续查看本次检查进度。                     │
└───────────────────────────────────────────────────────────────────┘
```

每项 Worker 进度显示名称、完成量/总量、状态、当前对象和已发现问题数；失败时展开安全的失败摘要。点击“暂停”后，按钮显示“正在暂停”，直至当前 Worker 单元完成并进入 `paused`；暂停状态展示“任务已暂停，数据库连接已释放”和 `[继续] [取消检查]`。服务重启恢复的任务显示“任务已暂停，等待继续”；因连接密码不持久化，点击继续时重新提交连接信息，再从后端返回的持久化检查点恢复。完成后自动跳转报告页；部分失败显示“已完成（部分对象未检查）”并提供报告入口；失败保留重试和返回编辑入口。

### 5. 问题详情抽屉

```text
┌──────────────────────────────────────────────────────────────┐
│ 金额字段使用 FLOAT                                      [×]   │
│ [紧急]  规则：TYPE-003    对象：app_db.orders.amount           │
├──────────────────────────────────────────────────────────────┤
│ 检测证据：amount 类型为 float，当前精度不可精确表示十进制金额。  │
│ 影响说明：聚合或对账可能出现精度误差。                           │
│ 建议：人工确认数据范围后迁移为 DECIMAL(18,2)。                   │
│                                                              │
│ DML 修复建议（需人工复核，未自动执行）                          │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ UPDATE `orders` SET `amount` = ROUND(`amount`, 2)         │ │
│ │ WHERE `amount` <> ROUND(`amount`, 2);                     │ │
│ └──────────────────────────────────────────────────────────┘ │
│ [复制 SQL]                    [标记为已知问题]                │
└──────────────────────────────────────────────────────────────┘
```

紧急问题必须展示 DML 修复方案，以及执行前校验、分批/事务建议和回滚说明；所有 DML 默认仅供复制或下载，不能由前端直接执行。若问题还需要 DDL 修复，DML 区域展示数据核验/迁移准备脚本，DDL 另行标注为需人工执行的建议。
