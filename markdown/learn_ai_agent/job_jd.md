### 4. Agent 架构师 / 资深开发工程师

**工作内容**

- Multi-Agent 工作流编排
  - 摒弃“单一超长 Prompt”的粗放方式，设计并落地专职 Agent 阵列。
  - 按职责拆分意图拆解、规则合成、逻辑自洽校验、资产匹配等 Agent。
  - 构建基于图或状态机的调度系统。
- “幻觉”防御与确定性闭环
  - 针对 LLM 输出的不确定性，使用 JSON Schema、Function Calling 等方式实施强约束的结构化输出策略。
  - 通过 Reviewer Agent 的静态逻辑推演机制，拦截“死锁、不可达状态、数值崩溃”等致命逻辑错误。
  - 设计错误打回与自动修复链路。
- 模型路由与成本工程
  - 根据 Claude Opus / Sonnet 5.x、GPT-5.5、Qwen 3.x、DeepSeek V4 Pro 等主流模型的特点，设计“质量 - 成本 - 延迟”分层路由策略。
  - 关键链路使用重模型保底。
  - 高并发或简单任务使用轻量级 / 开源模型摊薄成本。
- AI 评测与可观测体系
  - 搭建模型生成质量的自动化评测集与回归测试机制。
  - 除验证代码能否运行外，还需验证业务逻辑是否正确。
  - 建立 Prompt 与 DSL Schema 的版本管理和灰度发布能力。

**关键技能**

- 工程化代码能力：具备 3 年以上 Python 后端开发或架构经验，以及良好的系统分层、接口抽象和工程化落地能力，而非仅能编写脚本。
- Multi-Agent 系统实战经验：具备基于图或状态机落地多 Agent 协作系统的经验；精通 LangGraph、AutoGen、CrewAI 等框架的底层原理，或有脱离框架、基于原生 API 编写 Agent 调度器的经历。
- 结构化输出控制能力：熟练运用 JSON Schema、Function Calling 等技术，能将大模型的发散输出约束在严格指定的格式内，并具备生产环境中处理格式异常和兜底的经验。
- 数据驱动的架构认知：理解编译原理（AST、解释器执行逻辑）或熟练掌握 ECS（实体 - 组件 - 系统）架构思想，能够将复杂业务逻辑抽象为纯数据描述（如 JSON）。
